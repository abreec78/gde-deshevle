# Где дешевле?

## Локальная версия по утверждённым макетам

Ветка `codex/marketplace-redesign` содержит адаптивную главную и сравнение SSD
по двум PNG владельца. Новая проверка и ограничения: [PROJECT_STATUS.md](PROJECT_STATUS.md).
Изображения — локальные оптимизированные WebP, зависимости и сборка не нужны.
Поиск, 12 категорий, сортировка с доставкой и избранное сохранены. Категории
приведены к утверждённому макету; демокаталог содержит 12 товаров, главная — 6 популярных.
Цены, характеристики и история иллюстративные; реальные магазины не подключены.

Для запуска используйте HTTP-сервер ниже. `node --test` запускает 38 тестов
логики и PWA. В браузере проверьте главную, «Компьютеры и комплектующие» → SSD → 1 ТБ,
поиск, фильтры, избранное и перезагрузку. Бизнес-логика находится в `core.js`,
интерфейс — в `app.js`, оформление — в `styles.css`.

PWA устанавливается на Android из меню браузера, на iPhone — через Safari →
«Поделиться» → «На экран Домой» после развёртывания по HTTPS. Есть manifest,
иконки 192/512, apple-touch-icon, оболочка и изображения в офлайн-кеше.
Инструкцию можно открыть кнопкой «Как установить?». Установка на реальных
устройствах пока не проверена. Избранное локально для origin/профиля, между
устройствами не синхронизируется. Страница должна обслуживаться из корня
репозитория или подкаталога без изменения относительных путей.

Версия пока не опубликована и не отправлена в GitHub. PR №2 не объединён.

Веб-приложение для сравнения цен на товары российского рынка.

## Требования к первой рабочей версии
- Удобная мобильная и настольная версия.
- Поиск по товарам, категории, фильтры и сортировка по цене.
- Карточка товара: название, изображение, магазин, цена, дата обновления, ссылка на магазин.
- Отображение источника и актуальности цены; никаких выдуманных цен или скидок.
- Раздел избранного.
- Отслеживание переходов без сбора лишних персональных данных.
- PWA с установкой на телефон.
- Административный способ обновлять каталог.

## Важные ограничения
Пока не подключены разрешённые источники цен и партнёрские программы, демонстрационные данные должны быть явно помечены. Нельзя выдавать тестовые данные за актуальные предложения. Рекламный бюджет 3000 ₽ не расходуется без подтверждения владельца.

## Этапы
1. Рабочий интерфейс и проверка владельцем.
2. Исправления и доведение функций до согласованного состояния.
3. Подключение источников цен и проверка ссылок.
4. Публикация и только после одобрения тест рекламы.

## Локальный запуск и проверки

Из корня репозитория, Python 3:

```sh
python -m http.server 8872 --bind 127.0.0.1
```

Открыть `http://127.0.0.1:8872/`. Для service worker нужен localhost/HTTPS,
а не открытие index.html как файла. Если порт занят, выбрать свободный.

Автоматические проверки, Node.js 22 или новее, без установки пакетов:

```sh
node --test tests/app.test.cjs
```

Тесты выполняют настоящую бизнес-логику `core.js` и service worker в изолированном
контексте с заменами кеша/сети. Проверяют поиск, 12 категорий, итоговые цены,
сортировку, комбинации фильтров, избранное, повреждённое/недоступное хранилище,
офлайн-ответы, обновление кеша и относительные пути. Это не замена браузерной
проверки вёрстки и установки PWA на реальных устройствах.

Свежая браузерная проверка: [PROJECT_STATUS.md](PROJECT_STATUS.md).
История проверки исходного PR2: [docs/PR2_VERIFICATION.md](docs/PR2_VERIFICATION.md).

GitHub Actions запускает весь набор командой `node --test` на Node.js 24
при открытии, обновлении коммитов и повторном открытии любого Pull Request.
Workflow: `.github/workflows/tests.yml`. Установка npm-пакетов не требуется.
Workflow только проверяет код: не публикует приложение и не объединяет PR.
