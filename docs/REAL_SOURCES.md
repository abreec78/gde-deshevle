## Что уже работает локально

`ingestion/import_feed.py`: получение разрешённого HTTPS YML (до 20 МБ),
проверка доменов, свежести, рублёвых цен, ссылок, фотографий и характеристик;
только явно разрешённые источники. XML с DTD/entities запрещён, редиректы
требуют явного конечного URL. URL фида и Authorization остаются в окружении.
Документация поддерживаемого [формата YML](https://yandex.ru/support/merchants/ru/connect/form-feed).
Это описание формата, а не разрешение на использование любого найденного фида.

Реестр `ADAPTERS` позволяет добавлять нормализаторы новых форматов. Пока
реализован только YML; непроверенные Ozon/WB/DNS endpoints не выдумывались.
Формат конкретного партнёрского фида надо сверить после выдачи доступа.

В одной конфигурации поддерживается до 10 источников одного региона. Категории
из фида сопоставляются с 12 категориями интерфейса через `categoryMap`.
Неизвестные категории, неверные цены и неразрешённые URL не экспортируются.
Пустой/ошибочный фид не затирает предыдущую успешную загрузку. Товары,
исчезнувшие из успешного фида, снимаются с активной выдачи. Сбой источника
сохраняет прежние данные лишь до срока годности, а не обновляет их timestamp.

Идентификация: корректный GTIN с контрольной цифрой либо точный бренд+MPN;
ёмкость/цвет/комплект отделяются. Без сильного идентификатора товар остаётся
отдельным внутри источника. Нечёткое совпадение названий не считается одним
товаром. При различающемся заполнении атрибутов возможны раздельные карточки:
лучше не объединить, чем сравнить разные комплектации.

`work/catalog.sqlite` содержит текущие предложения, журнал импортов и
наблюдения цены/доставки/региона. Секретов и исходных URL фидов в БД нет.
JSON `data/catalog.json` — публичная проекция; UI не получает доступ к БД.
Для каждого предложения экспортируется до 365 наблюдений. Ограничение снимка
4 МБ защищает браузер; при превышении экспорт прекращается, старый JSON
не перезаписывается. Для большого каталога следующий этап — серверная БД/API
с пагинацией, а не бесконечное увеличение статического JSON.

Цена доставки принимается из фида только при `deliveryVerified: true`, когда
документально подтверждены регион и условия. Разные варианты стоимости не
превращаются в минимальную «доставку от нуля». Иначе доставка `null`, итог
неизвестен. Все известные итоги включают доставку. Ложное наличие не рисуется.

Реальные и демонстрационные данные разделены переключателем. По умолчанию
открывается реальный режим: сейчас он пуст. Ошибка загрузки не включает демо
автоматически. Демоверсия, её фото, фильтры и числовые ID избранного сохранены.
Реальные ID начинаются с `live:` и тоже сохраняются в избранном. Предложения
старше 24 часов исключаются; TTL проверяется и в офлайне, каждую минуту.
История в реальном режиме строится из наблюдений одного предложения,
цена товара без доставки явно обозначена; при одном наблюдении график не
выдумывается. Даты проверки и регион отображаются рядом со ссылкой магазина.

## Облако без компьютера владельца

Подготовлен `.github/workflows/refresh-catalog.yml`: каждые 6 часов импорт,
восстановление SQLite из кеша, тесты, выпуск JSON/БД как артефакта. Запуск
заблокирован, пока `REAL_INGESTION_ENABLED != true`, и разрешён только в
публичном репозитории на стандартном runner. [GitHub подтверждает бесплатность
таких запусков](https://docs.github.com/en/actions/concepts/billing-and-usage).

**Workflow сейчас локальный, не отправлен и не запущен.** Расписания GitHub
исполняются с default branch; включение потребует отдельного разрешения на
добавление workflow туда. Это не требует автоматического объединения PR №2.
Артефакты хранятся 7 дней, cache — вспомогательный, не гарантированное вечное
хранилище. БД надо регулярно резервировать; для длительной эксплуатации
нужна согласованная постоянная БД. Сейчас облачные ресурсы не создавались.

Workflow **не публикует JSON в работающий сайт и не делает git push/deploy**.
После разрешения публикации нужен отдельный контролируемый шаг доставки
снимка в `data/catalog.json` хостинга либо отдельный публичный read-only API.
До этого нельзя утверждать, что опубликованный сайт обновляется автоматически.

## Конкретный следующий шаг владельца

1. Открыть [подключение Маркета](https://yandex.ru/project/distribution/information/)
   и получить в кабинете/у менеджера разрешённый товарный фид категории SSD
   для публикации в агрегаторе. Нужен URL настоящего фида, его формат, регион,
   условия доставки, срок обновления и разрешение на использование фото/цен.
   Регистрация и договорные согласования не выполнялись за владельца.
2. Секретный URL хранить в GitHub Actions secret `SOURCE_FEEDS_JSON`, а не в
   переписке, исходниках или фронтенде. Пример без ключей:
   `ingestion/sources.example.json`. Заменить URL/домены/categoryId реальными,
   и только после получения разрешения поставить `authorized: true`.
   Если фид требует заголовок Authorization, указать `authorizationEnv` и
   задать соответствующее значение в среде импортера; для workflow используйте secret `FEED_AUTHORIZATION` и `authorizationEnv: "FEED_AUTHORIZATION"`. Значение не попадёт в JSON.
3. После получения доступа сверить фактическую схему фида, провести первый
   настоящий импорт и контроль цен/фото/моделей. Лишь затем разрешить отправку
   кода, включение облачного расписания и отдельно публикацию снимка.

Локальные команды (Python 3.12+, Node 24):

```sh
python -m unittest discover -s tests -p 'test_*.py'
node --test
# SOURCE_FEEDS_JSON задаётся локально безопасным способом, не в командной истории
python ingestion/import_feed.py --db work/catalog.sqlite --output data/catalog.json
```

Без конфигурации выполнен настоящий локальный запуск импортера: 0 источников,
0 товаров, 0 ошибок. Синтетические фиды используются только тестами во временных
папках и никогда не помещаются в публичный каталог как настоящие товары.
