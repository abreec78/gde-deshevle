# Радар жизни — Android 0.5

Основной клиент — телефон. Нативный Android / Java / стандартные Views, Android 8.0+ (API 26), target/compile SDK 36. Отдельный проект, веб-кабинет не изменён.

## Интерфейс
Одноразовое знакомство на одном экране с ползунком активации. Тёмный объёмный стиль, карта с лучами, скрытая за кнопкой лента. Карта открывает направления. В Темах доступны 12 направлений, 162 узла и 129 конечных подписок, поиск и переключатели всего раздела/ветки/листа. Частичный выбор отмечается счётчиком. Старая настройка категорий мигрирует в подтемы при первом чтении. В настройках можно повторно открыть знакомство.

## Источники и реальные данные
Есть 3 проверенные АРХИВНЫЕ карточки: два указания Банка России по ОСАГО (7368-У, 7349-У), приказ ФНС о 3-НДФЛ (913@). Это не вымышленные демонстрационные события и не сегодняшние новости. Даты и прямые официальные ссылки показаны в карточках.

Основная точка загрузки: https://kupiora.ru/radar/legal-feed.json . В APK вложена последняя проверенная подборка для первого запуска без сети. Кнопка Проверить обновления запрашивает опубликованный JSON. Изменения правовых норм не подменяются научными статьями или мнениями.

Официальная RSS нормативных актов Банка России работает. Ежедневный серверный конвейер получает акты, делает ПРЕДВАРИТЕЛЬНУЮ разметку по названиям и сохраняет очередь. Автоадаптеры ФНС и Минздрава тоже выполняют попытки; ошибки доступа отражаются в статусах и не маскируются успехом. Справочные ссылки других ведомств не являются подключённым импортом.

Новая карточка с понятной выжимкой требует проверки и добавления в legal-reviewed.json. reviewed=true автоматически не выставляется. Поэтому новые готовые объяснения пока НЕ гарантированы каждый день, даже если импорт принёс новые документы. Очередь доступна в разделе Источники как документы без выжимки; уведомления по ней не отправляются. Это не полное покрытие законодательства РФ.

## Ежедневный сбор и память
Сервер: GitHub Actions daily-legal.yml, плановый cron 0 6 * * * (около 09:00 МСК). GitHub может задержать запуск. Каждый запуск сохраняет legal-feed.json и датированный legal-history/YYYY-MM-DD.json в GitHub и публикует Pages. Это общедоступные нормативные данные, без настроек и личных сведений пользователей.

## Сводки
Выбор: раз в день, раз в 3 дня, раз в неделю, раз в месяц. Независим от серверного сбора. Дневной — интервал от предыдущей сводки/начала наблюдения; месячный — календарный месяц, а не 30 дней. Новые готовые карточки складываются в локальную очередь. Первая синхронизация создаёт базу без рассылки старых записей. При отправке фильтр выбранных подтем применяется повторно; дубли подавляются. Пустая сводка не отправляется. Разрешение Android на уведомления запрашивается отдельно.

Доставка пока через JobScheduler (периодическая суточная проверка). Это НЕ серверный push: Android может отложить запуск, особенно при экономии батареи/принудительной остановке. Для гарантированного серверного расписания доставки потребуется отдельный push-провайдер. При отсутствии разрешения уведомления остаются в очереди. Тестовая кнопка явно подписана как тест.

## Хранение настроек
Приватные SharedPreferences radar: topicSelectionV1, старые categories, digest_interval, digest_last, digest_pending, feed, seen, has_baseline, onboarded. Выбор медицинских направлений остаётся на устройстве, в GitHub и на сервер не отправляется. Резервное копирование Android отключено. Удаление приложения удаляет локальные настройки. Для будущих стран в каталоге/потоке есть jurisdiction; текущий клиент принимает только RU.

## Сборка и проверка
Открыть папку в Android Studio, установить SDK 36/JDK 17+. Используются доступные в среде AGP 9.4.0 и Gradle 9.6.0.
`gradlew.bat assembleDebug lintDebug testDebugUnitTest`
APK: app/build/outputs/apk/debug/app-debug.apk. Это debug-сборка для теста, не подписанный магазинный релиз. local.properties не включается в переносимый архив.

Тесты проверяют официальные URL/типы документов, даты, теги, изоляцию веток, отсутствие дублей и календарные интервалы сводок. Сценарии эмулятора проверяют переходы, сохранение выбора и фактическую фильтрацию ленты.

Будущий раздел Цены и расходы записан как идея в исследовании; текущая версия его не подключает.
