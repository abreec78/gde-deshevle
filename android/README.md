# Радар жизни — Android 0.9

Основной клиент — телефон. Нативный Android / Java / стандартные Views, Android 8.0+ (API 26), target/compile SDK 36. Отдельный проект, веб-кабинет не изменён.

## Интерфейс
Одноразовое знакомство на одном экране с ползунком активации. Тёмный объёмный стиль, карта с лучами, скрытая за кнопкой лента. Карта открывает направления. В Темах доступны 12 направлений, 159 узлов и 118 конечных подписок, поиск и переключатели всего раздела/ветки/листа. Частичный выбор отмечается счётчиком. Старая настройка категорий мигрирует в подтемы при первом чтении. В настройках можно повторно открыть знакомство.

## Источники и реальные данные
Есть 3 проверенные АРХИВНЫЕ карточки: два указания Банка России по ОСАГО (7368-У, 7349-У), приказ ФНС о 3-НДФЛ (913@). Это не вымышленные демонстрационные события и не сегодняшние новости. Даты и прямые официальные ссылки показаны в карточках.

Основная точка загрузки: https://kupiora.ru/radar/legal-feed.json . В APK вложена последняя проверенная подборка для первого запуска без сети. Кнопка Проверить обновления запрашивает опубликованный JSON. Изменения правовых норм не подменяются научными статьями или мнениями.

Официальная RSS нормативных актов Банка России работает. Ежедневный серверный конвейер получает акты, делает ПРЕДВАРИТЕЛЬНУЮ разметку по названиям и сохраняет очередь. Автоадаптеры ФНС и Минздрава тоже выполняют попытки; ошибки доступа отражаются в статусах и не маскируются успехом. Справочные ссылки других ведомств не являются подключённым импортом.

Новая карточка с понятной выжимкой требует проверки и добавления в legal-reviewed.json. reviewed=true автоматически не выставляется. Поэтому новые готовые объяснения пока НЕ гарантированы каждый день, даже если импорт принёс новые документы. Очередь доступна в разделе Источники как документы без выжимки; уведомления по ней не отправляются. Это не полное покрытие законодательства РФ.

## Ежедневный сбор и память
Сервер: GitHub Actions daily-legal.yml, плановый cron 0 6 * * * (около 09:00 МСК). GitHub может задержать запуск. Каждый запуск сохраняет legal-feed.json и датированный legal-history/YYYY-MM-DD.json в GitHub и публикует Pages. Это общедоступные нормативные данные, без настроек и личных сведений пользователей.

## Сводки
Выбор: раз в день, раз в 3 дня, раз в неделю, раз в месяц. Независим от серверного сбора. Дневной — интервал от предыдущей сводки/начала наблюдения; месячный — календарный месяц, а не 30 дней. Новые готовые карточки складываются в локальную очередь. Первая синхронизация создаёт базу без рассылки старых записей. При отправке фильтр выбранных подтем применяется повторно; дубли подавляются. Пустая сводка не отправляется. Разрешение Android на уведомления запрашивается отдельно.

Доставка пока через JobScheduler (периодическая суточная проверка). Это НЕ серверный push: Android может отложить запуск, особенно при экономии батареи/принудительной остановке. Для гарантированного серверного расписания доставки потребуется отдельный push-провайдер. Если системные уведомления запрещены, сводка сохраняется во внутреннем центре уведомлений; системный значок требует разрешения. Тестовая кнопка явно подписана как тест.

## Хранение настроек
Приватные SharedPreferences radar: topicSelectionV1, старые categories, digest_interval, digest_last, digest_pending, feed, seen, has_baseline, onboarded. Выбор медицинских направлений остаётся на устройстве, в GitHub и на сервер не отправляется. Резервное копирование Android отключено. Удаление приложения удаляет локальные настройки. Для будущих стран в каталоге/потоке есть jurisdiction; текущий клиент принимает только RU.

## Сборка и проверка
Открыть папку в Android Studio, установить SDK 36/JDK 17+. Используются доступные в среде AGP 9.4.0 и Gradle 9.6.0.
`gradlew.bat assembleDebug lintDebug testDebugUnitTest`
APK: app/build/outputs/apk/debug/app-debug.apk. Это debug-сборка для теста, не подписанный магазинный релиз. local.properties не включается в переносимый архив.

Тесты проверяют официальные URL/типы документов, даты, теги, изоляцию веток, отсутствие дублей и календарные интервалы сводок. Сценарии эмулятора проверяют переходы, сохранение выбора и фактическую фильтрацию ленты.

Будущий раздел Цены и расходы записан как идея в исследовании; текущая версия его не подключает.

Уточнение ОСАГО: КБМ выделен из тарифа по повторяющимся обращениям, фиксируемым Банком России; отдельно раскрыты территориальные коэффициенты, условия европротокола, оформление ДТП, ремонт и страховые споры. Это правовые сценарии, не комбинации характеристик автомобиля.

Решение пользователя от 04.11.2026: диагнозы в этой версии не выбираются. Удалены диабет, астма/ХОБЛ, щитовидная железа, состояния после инфаркта/инсульта и другие диагностические ветки. Сохраняются медицинские направления и общие права/обеспечение. Выбор старого дочернего диагноза переносится на соответствующее направление.

Версия 0.6: медицинские направления без диагнозов. После обновления каталога выполняется свежая синхронизация. Архивные карточки никогда не формируют уведомление о новом изменении.

Версия 0.7: порядок направлений — здоровье, выплаты, жильё, работа, семья, образование, налоги, покупки, связь, автомобиль, бизнес, экология. Это редакционная расстановка по широте жизненных ситуаций, не измеренный рейтинг поисковой популярности. Компактные шевроны с числом непосредственных подразделов раскрывают вложенные переключатели внутри карточки. Идентификаторы тем и сохранённый выбор остаются прежними.

## Версия 0.9 — оформление и уведомления
Нижнее меню: Радар, Темы, Настройки. Темы — только интересы и компактные раскрытия. Настройки — оформление, период сводок, разрешение уведомлений, повтор знакомства и маленькая ссылка на источники в конце. Прямые ссылки первоисточников карточек сохранены.

На всех основных экранах в шапке колокольчик с красным числом непрочитанных уведомлений. История и прочитанность сохраняются локально (notification_inbox, до 200 записей). Есть отметка одного/всех прочитанными; история при этом остаётся. При первом обновлении активные старые системные уведомления переносятся в центр. Архивные карточки не превращаются в новые уведомления. Тестовые записи явно помечены как тест.

Канал Android допускает значки (setShowBadge), уведомление передаёт число непрочитанных (setNumber). Внешний вид точки/числа на значке и её наличие определяются лаунчером, разрешениями и настройками Android. Свайп системного уведомления может убрать системную точку; внутренний счётчик остаётся до отметки прочтения. Приложение не навязывает постоянное системное уведомление и не изменяет иконку вручную. Справка: https://developer.android.com/develop/ui/views/notifications/badges .

Тёмная и Светлая темы переключаются в Настройках. Выбор ui_theme сохраняется на устройстве, применяется ко всему интерфейсу и системным панелям. По умолчанию остаётся тёмная тема.
